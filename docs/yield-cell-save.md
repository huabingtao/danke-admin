# 资源全景单元格局部保存

## 修改原因与范围

原产出数量保存成功后调用 `fetchYields()`，重新 GET 全部产出并设置整表 `loading`，导致正文行暂时卸载、滚动区域收缩。现改为使用原 `POST /yields` 返回的已保存记录更新对应本地记录，新增记录则追加。只修改 Admin 产出页及相关回归测试。

## 交互

- 保存期间仅锁定当前单元格，显示保存状态；其他单元格可继续编辑。
- 不重新请求全部产出，不切换整表加载状态，不主动修改滚动位置、筛选或排序。
- 根据服务器确认值更新数量、合计、概览及 Markdown 导出；金额变更仍按现有排序/仅看有产出规则自然调整行序或可见行。
- 同一单元格的回车、失焦及延迟事件不会重复提交；不同单元格独立保存，旧响应不会关闭新打开的其他编辑器。
- 未修改的值不提交；Escape 取消；失败保留草稿和旧值，标记出错单元格，可再次编辑重试。
- 编辑控件复用 shadcn Input。原路由、Token 及权限检查不变。

## 验证

- 4 个相关测试文件共 30 项通过，包含新增的 5 个局部保存场景；类型检查通过，ESLint 无错误，保留 6 条页面原有警告。
- 验证了表格 DOM/滚动容器不重建、滚动值保留、不产生额外列表请求、服务端确认值、创建/更新、重复提交、失败重试、异常响应、并行编辑、取消、合计及导出一致性。
- 仅使用模拟接口，未写入正式数据库。尚未进行实际浏览器视觉/交互验收。
- 独立副本 `/tmp/danke-admin-cell-save-lgxz0xwx` 使用 `npm run build -- --webpack` 构建通过，16.61 秒。默认 Turbopack 构建因副本的外部 node_modules 软链接报错；未修改项目构建配置，未覆盖运行中的 `.next`、`out`。

## 影响与回滚

不改 Core 或数据库，无需迁移。来源改名、删除确认和账号显示列流程沿用原逻辑。撤回 `app/yields/page.tsx` 本次单元格保存、状态及输入控件改动即可回滚；保留此前排序、分类和用户未提交工作。
